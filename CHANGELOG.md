# Changelog

One entry for every change under `slices/`, `bin/` or `lib/` that reaches `main`, newest first. `kit bump` prints the lines added between the old pin and the new one, so each line reads on its own.

An entry starts with `BREAKING:` when the change removes or renames a slice, file or parameter, adds a required parameter or heading, changes a hook's behaviour, or narrows a permission. A `BREAKING:` entry gives the exact edit to `.claude/kit.json` or `.claude/rules/repo.md` that a repo makes at the bump.

## 2026-10-23 — three-step setup: kit init writes kit.json, kit apply does the rest

- kit: `kit init` also writes `.claude/kit.json` when the repo has none, and never changes one that is there. It picks every slice except one whose `detect` paths the repo lacks, and fills each param whose `init` detector finds a value: `gate` from `scripts/check.sh` or package.json's check or test script, else `bash .claude/vendor/kit/bin/kit check`; `trunk`; `memory_root` from an existing CLAUDE.md import; `wiki_dir`. It prints each choice and where it came from, and a NOTICE for a value it could not find or that the param's pattern rejects.
- kit: new `kit apply [--discard]` creates what is missing, then renders and checks. Missing means: a repo.md heading a slice declares that is absent or empty (filled with the slice's default text), the memory index, the `@<memory_root>/MEMORY.md` line in CLAUDE.md and the `.claude/** text=auto eol=lf` line in .gitattributes, which keeps text files LF and leaves binary files alone. It never changes text already there, and never writes through a symlink that leads outside the repo. It exits with render's status when render fails, else with check's.
- kit: `kit scaffold` creates the same missing pieces without rendering. A kit.json it writes is now `kit init`'s, in place of core alone with an empty gate.
- kit: `kit check` prints a NOTICE while `gate` or `gate_landing` is `bash .claude/vendor/kit/bin/kit check`, which checks only the kit's own files, and while a param that `kit init` fills beside a detected folder names a folder that holds no pages besides `_index.md`. Its MEMORY and REPO lines end with `: run kit apply`.
- kit: new check row IGNORED fails while `.gitignore` matches `.claude/vendor/kit`, kit.json, the lock, settings.json, repo.md or a rendered file, since an ignored file is never committed.
- kit: render, check and status compare a rendered file's bytes as they are (`git hash-object --no-filters`). A CRLF copy of a rendered file, which a `.gitattributes` eol rule used to hide, is now DRIFT, and `kit apply --discard` writes it back.
- kit: `kit bump` refuses an ignored `.claude/vendor/kit` before it moves anything, with `bump: cannot stage the gitlink: .gitignore ignores .claude/vendor/kit`. Before, the half-done bump left the new pin staged, and the next bump missed its CHANGELOG lines.
- kit: slice.json may declare `detect` (paths that select the slice for a new kit.json) and, on a param, `init` (one of the detectors `check_command`, `default_branch`, `beside_detect`, `memory_import`). `slices/<slice>/repo.md` holds the default text of the slice's headings. The selftest lints `init-keys` and `headings` check both.
- core: allows `kit apply` bare, so `kit apply --discard` prompts. The `kit` skill runs `kit apply` after a bump and after an exclude, and its bump stages CLAUDE.md, .gitattributes and the memory folder as well as `.claude`. For `bump: cannot stage the gitlink` it now says to add `!/.claude/vendor/` below the `vendor/` line, which keeps other `vendor/` folders ignored, in place of anchoring the line.
- session-branch: default text for Deploy, Gate, Conflict stops and Branch names, each the strictest reading of the rule that reads it. `trunk` is detected: a local `main`, else the branch origin/HEAD names, else `master`, else the current branch. /merge-to-main quotes the gate NOTICE in place of "gate passed".
- hugo-wiki: picked for a new kit.json only where a `themes/hugo-book` path exists. `wiki_dir` becomes the `content` folder beside that theme when it holds pages besides `_index.md` (or `_index.<lang>.md`); otherwise `kit init` and `kit check` print a NOTICE asking for it.

## 2026-10-21 — v1: core, self-improvement, session-branch, hugo-wiki

- kit: the `kit` CLI. In a repo that vendors the kit: `scaffold`, `render`, `check`, `status`, `bump`, `init` and `edit`; a failed `bump` prints the CHANGELOG lines before it restores the old pin. In the kit's own clone: `selftest` and `publish`.

- core, mandatory in every repo: rules `tool-use`, `irreversible`, `source-control`, `permissions`, `collaboration` and `memory`; skill `kit` (status, bump, changing a rendered file); hooks `guard-write.sh` (PreToolUse on Edit, Write and NotebookEdit) and `kit-status.sh` (SessionStart). Params `gate` (required), `gate_landing` and `memory_root` (a path inside the repo: no leading `/`, no `..`). Allows `kit check`, `kit status` and `kit edit` with arguments and `kit render` only bare, so `kit render --discard` prompts. Sets `autoMemoryEnabled` and `disableAllHooks` to false. Forbids the broad `git`, `git -C`, `gh`, `npm` and `npx` allow entries, spelled any equivalent way or widened: `kit check` reads bare `Bash` as `Bash(*)`, trims and collapses whitespace inside `Bash(...)`, reads a trailing `:*` as ` *`, and fails on any entry whose text before its first `*` is a prefix of a forbidden one. A narrower entry that still reaches a forbidden command, such as `Bash(git push origin *)`, is not caught.
- core: the `kit` skill's bump section covers `bump: cannot stage the gitlink`, which an unanchored `vendor/` line in `.gitignore` causes by ignoring `.claude/vendor/kit`.
- core: the text of `tool-use` and `irreversible` comes from uniteum/ai, with thanks.
- self-improvement: rule `self-improvement` (friction notes, patterns, proposed rules) and a PermissionRequest hook that logs each permission prompt to `friction/project-prompt-log.md` under the memory root, except a prompt to write that log itself. Requires core.
- session-branch: rule `session-branches`; skills `merge-to-main` and `sync-with-main`; hooks `guard-git.sh` (PreToolUse on Bash: the trunk moves only by fast-forward, no branch is deleted, and in a repo with a kit lock no pushed ref pins a kit commit that is not on the kit's origin/main) and `branch-context.sh` (SessionStart; reports a kit checkout left off-pin by a branch switch apart from uncommitted work). Params `trunk` and `remote`; `repo.md` headings Deploy, Gate, Conflict stops and Branch names. Requires core.
- session-branch: admitted by the owner with its two consumers named, gyrealm/gyrealm and gargantis/amorfus.
- hugo-wiki: rules `wiki-linking`, `wiki-content` and `wiki-workflow`, always on, and `hugo-on-workers`, scoped to `hugo.toml`, `wrangler.*`, `layouts/` and `scripts/`. Param `wiki_dir`. Allows `hugo` builds and the local server; `hugo deploy` prompts. Requires core.
